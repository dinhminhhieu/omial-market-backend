## Quy ước khi thêm tính năng mới

1. Thêm pattern vào `patterns/<service>/<resource>.patterns.ts` (RPC = `<resource>.<action>`; event = `<service>.<đã_xảy_ra>`).
2. Thêm DTO payload + response vào `dto/<service>/<resource>/{req,res}/`.
3. Export ở `index.ts`.
4. Gateway `send()`/`emit()` và service `@MessagePattern`/`@EventPattern` dùng CHUNG hằng + DTO này.

### Mẫu option (template) — quyết định kiến trúc

- 2 model mới trong schema: `OptionTemplate` + `OptionTemplateItem` (KHÔNG có `productId` — thư viện dùng chung).
- "Áp mẫu" = **COPY (snapshot)** template → `ProductOptionGroup/Item` của sản phẩm. Copy xong độc lập (sửa sp không đụng mẫu). KHÔNG auto-propagate (mâu thuẫn với sửa riêng từng sp).
- `OptionTemplate.name` `@unique`. Không lưu `sourceTemplateId` (YAGNI — thêm khi cần dedup/bulk-sync).
- **Template GIẢI Ở FRONTEND**: wizard tạo sp cho user chọn mẫu → sửa trên form → FE gửi data cuối. Nên:
  - `CreateProductDto.productOptionGroups?: ProductOptionGroupInputDto[]` (nested, `OmitType` bỏ `productId`) — service tạo product + groups trong **1 `$transaction`**. FE KHÔNG gửi templateId.
  - Template chỉ cần `GET`/CRUD để FE fetch picker. `OPTION_TEMPLATE_PATTERNS` = **CRUD gọn** (update đồng bộ items kiểu diff/sync). Đã BỎ `ITEM_ADD/UPDATE/DELETE` + `APPLY_TO_PRODUCT` (dư — không luồng nào dùng; YAGNI). Cần bulk-apply sau thì thêm lại.
  - Update template: `optionTemplateItems?` với item `id` optional (`UpsertOptionTemplateItemDto`) — có id = sửa, không id = thêm, vắng mặt = xoá.
- ⚠️ "1 API tạo tất cả" ở gateway KHÁC "1 transaction": product+option chung DB (ok), nhưng **kho thuộc inventory-service DB riêng** → cần Saga (Phase 2). Variant + kho để riêng.
- Nên viết ADR `docs/adr/` cho quyết định copy-vs-reference này.
